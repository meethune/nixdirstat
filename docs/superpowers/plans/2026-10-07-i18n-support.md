# i18n Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add internationalization support to NixDirStat so all user-facing strings can be translated, with a complete English baseline catalog.

**Architecture:** Use `rust-i18n` v4 for compile-time string catalog baking with zero-allocation `t!()` lookups. Use `sys-locale` for environment-based locale detection. A `--lang` global CLI flag overrides the detected locale. All ~130 user-facing strings are extracted to `locales/en.yml` with hierarchical dot-separated keys.

**Tech Stack:** `rust-i18n = "4"`, `sys-locale = "0.3"`, `unicode-width = "0.2"` (already a dependency)

**Spec:** `docs/superpowers/specs/2026-10-07-i18n-design.md`

## Global Constraints

- Rust stable, edition 2024, MSRV 1.95
- `unsafe` code is forbidden
- No `#[allow(...)]` to bypass clippy (except verified false positives with comments)
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` must pass
- Conventional Commits for all commit messages
- Size units (`B`, `KiB`, `MiB`, `GiB`, `TiB`) are IEC standards — do not translate
- CLI `--help` text stays in clap derive doc comments — do not extract
- Internal/debug error messages stay untranslated
- All `t!()` calls use the key naming convention from the spec: `{component}.{area}.{name}`

## Review Focus

1. **Missing catalog key** — a `t!("key")` call where the key doesn't exist in `locales/en.yml` silently returns the key string itself. Tests must catch this for a representative sample.
2. **Interpolation variable mismatch** — a `t!("key", foo = x)` where the YAML template uses `%{bar}` instead of `%{foo}` silently drops the variable. The catalog completeness test should verify interpolated strings render with actual values.
3. **Display width regression in format-padded columns** — after switching `FileCategory` Display to `t!()`, the `format!("{ext_label:<ext_width$}")` in `extension_legend.rs:80` and `format!("{name:<name_width$}")` in `dir_tree.rs:118` still use char-count padding. The `pad_display_width` helper must be applied.
4. **Locale code normalization edge cases** — `sys_locale::get_locale()` may return `"C"`, `"POSIX"`, `""`, or `None`. `init_locale` must normalize these to `"en"`.
5. **`localized_message()` missing a user-facing variant** — if a new error variant is added later without updating `localized_message()`, the catch-all arm silently falls back to English `#[error]`. A test should verify all user-facing variants are covered.

```rust
pub fn init_locale(cli_override: Option<&str>) {
    let locale = cli_override
        .map(String::from)
        .or_else(|| sys_locale::get_locale())
        .map(|s| {
            s.split('.')
                .next()
                .unwrap_or(&s)
                .replace('_', "-")
        })
        .unwrap_or_else(|| "en".to_string());

    rust_i18n::set_locale(&locale);
}
```

```rust
pub(crate) fn pad_display_width(s: &str, width: usize) -> String {
    use unicode_width::UnicodeWidthStr;
    let display_width = UnicodeWidthStr::width(s);
    let padding = width.saturating_sub(display_width);
    format!("{s}{}", " ".repeat(padding))
}
```
