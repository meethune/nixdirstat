# Internationalization (i18n) Support — Design Spec

**Issue:** #53
**Date:** 2026-10-07
**Status:** Draft

## Goal

Extract all user-facing strings into a localization layer so NixDirStat can be translated into other languages. Ship an English baseline catalog. No non-English translations ship initially — the framework enables community contributions.

## Scope

### In scope

- Extract ~130 hardcoded user-facing strings into translation keys
- English string catalog as the complete baseline
- Locale detection from environment variables
- `--lang` CLI flag to override detected locale
- Fallback to English when a translation is missing or locale is unknown
- `TRANSLATING.md` contributor documentation

### Out of scope

- Non-English translations (community-contributed after framework lands)
- Right-to-left (RTL) layout support
- Locale-specific number/date formatting
- CLI `--help` text translation (stays in clap derive doc comments)
- Internal/debug error message translation
- Size unit translation (`B`, `KiB`, `MiB`, `GiB`, `TiB` — IEC standards)

## Decision: `rust-i18n`

**Chosen over:** `fluent-bundle`, `i18n-embed-fl`, `gettext-rs`

**Rationale:**

- **Zero-allocation lookups** for static strings (`Cow::Borrowed(&'static str)`), critical for 60fps TUI render loop. Fluent allocates a new `String` per call.
- **Pure Rust, no C dependencies.** `gettext-rs` requires `libintl` (LGPL static linking concern).
- **Simple API.** `t!("key")` macro anywhere in the codebase. No bundle management, no error vectors.
- **CLDR pluralization is unnecessary.** Audit found exactly 1 plural branch in ~130 strings. All others are static labels or simple `"Label: {value}"` patterns. `rust-i18n`'s manual `one`/`other` keys are sufficient.
- **Mature.** 505K downloads/month, v4.2.4, actively maintained by Longbridge.
- **Fallback chain.** Built-in `fallback = "en"` with automatic territory stripping (`zh-CN` → `zh`).

## Architecture

### Dependencies

```toml
[dependencies]
rust-i18n = "4"
sys-locale = "0.3"
```

### Crate-Level Setup

In `lib.rs`:

```rust
rust_i18n::i18n!("locales", fallback = "en");
```

This macro scans `locales/` at compile time, bakes all translations into a static `HashMap`, and provides the `t!()` macro. Missing keys in non-English locales silently return the English string.

### Locale Detection & `--lang` Flag

**Precedence (highest to lowest):**

1. `--lang` CLI flag (e.g., `nixdirstat --lang fr scan /home`)
2. `sys_locale::get_locale()` (reads `LC_ALL` > `LC_MESSAGES` > `LANG`)
3. `"en"` hardcoded fallback

**CLI change** — add `--lang` as a global arg on the top-level `Cli` struct:

```rust
#[arg(long, global = true)]
pub lang: Option<String>,
```

`global = true` makes it work with any subcommand.

**Initialization function** — a single public function in `lib.rs`:

```rust
pub fn init_locale(cli_override: Option<&str>) {
    let locale = cli_override
        .map(String::from)
        .or_else(|| sys_locale::get_locale())
        .map(|s| {
            s.split('.')
                .next()
                .unwrap_or(&s)
                .replace('_', "-")
        })
        .unwrap_or_else(|| "en".to_string());

    rust_i18n::set_locale(&locale);
}
```

Called in `main.rs` after clap parsing, before dispatching to any subcommand. `rust-i18n` handles further fallback stripping internally.

## Catalog Structure

### File Layout

```
locales/
  en.yml        # English baseline (always complete)
  fr.yml        # French translation
```

One YAML file per locale (`_version: 1` format). Each file contains flat
key-value pairs for a single language. Future community translations add
`de.yml`, `ja.yml`, etc.

### Key Naming Convention

Dot-separated hierarchical keys mirroring the code's module structure:

| Prefix | Scope | Example |
|--------|-------|---------|
| `explorer.*` | Explorer view — panels, status, help, popups | `explorer.panel.directory-tree` |
| `progress.*` | Progress/scanning view | `progress.scanning` |
| `preview.*` | File preview errors | `preview.error.binary` |
| `file-type.*` | FileType Display impl | `file-type.dir` |
| `file-category.*` | FileCategory Display impl | `file-category.code` |
| `batch.*` | Batch mode stderr output | `batch.scan-complete` |
| `error.*` | User-facing error messages | `error.scan-root-not-found` |
| `ui.*` | Misc UI strings | `ui.rescan-unavailable` |
| `widgets.*` | Widget-specific strings | `widgets.extension-legend.none` |

### Pluralization

`rust-i18n` uses separate keys for plural forms:

```yaml
explorer.status.warnings:
  one: " %{count} warning (w) "
  other: " %{count} warnings (w) "
progress.files-gauge:
  one: "%{count} file"
  other: "%{count} files"
```

Only 2 strings in the catalog require plural forms.

### Full English Catalog

~130 keys total. Categories by count:

| Category | Count | Key prefix |

## Integration Points

### 1. TUI Rendering (~100 strings)

Direct `t!()` calls replacing hardcoded string literals:

```rust
// Static label — zero allocation (Cow::Borrowed)
let title = t!("explorer.panel.directory-tree");

// Interpolated — one allocation (Cow::Owned)
let status = t!("explorer.status.free", free = free, total = total);
```

`Cow<'static, str>` plugs directly into Ratatui's `Span::raw()` and `Line::from()` via `Into<Cow<str>>`.

### 2. Display Impls (~16 strings)

`FileType` and `FileCategory` Display impls call `t!()`:

```rust
impl fmt::Display for FileType {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let s = match self {
            Self::File => t!("file-type.file"),
            Self::Dir => t!("file-type.dir"),
            // ...
        };
        f.write_str(&s)
    }
}
```

### 3. Batch Mode Output (~5 strings)

Progress and completion messages in `lib.rs`:

```rust
eprintln!("{}", t!("batch.scan-complete", count = count, size = size));
```

### 4. User-Facing Errors (~5 strings)

Keep `#[error("...")]` intact for internal/debug use. Add `localized_message()` on error enums:

```rust
impl ScanError {
    pub fn localized_message(&self) -> Cow<'static, str> {
        match self {
            Self::RootNotFound(p) => t!("error.scan-root-not-found", path = p.display()),
            Self::NotADirectory(p) => t!("error.scan-root-not-directory", path = p.display()),
            _ => Cow::Owned(self.to_string()),
        }
    }
}
```

`main.rs` calls `localized_message()` for top-level error display. Internal pipeline/channel errors pass through untranslated.

The method is added to `ScanError` and `StorageError` (the two enums with user-facing variants like path-not-found and schema-mismatch). `PipelineError` and `UiError` are internal — they keep their `#[error]` strings only.

### What Stays Untouched

- CLI `--help` text (clap derive doc comments)
- Internal error variants (pipeline channel closed, storage writer failed, etc.)
- Size units (`B`, `KiB`, `MiB`, `GiB`, `TiB`)
- Debug/log messages

## Testing

### Catalog Completeness

```rust
#[test]
fn english_catalog_is_complete() {
    rust_i18n::set_locale("en");
    assert_ne!(t!("explorer.panel.directory-tree"), "explorer.panel.directory-tree");
    assert!(t!("explorer.panel.directory-tree").contains("Directory Tree"));
}
```

If `t!()` returns the key name, the catalog is missing that entry.

### Fallback Behavior

```rust
#[test]
fn unknown_locale_falls_back_to_english() {
    rust_i18n::set_locale("xx");
    assert!(t!("explorer.panel.directory-tree").contains("Directory Tree"));
}
```

### Locale Initialization

Test `init_locale` with explicit override, environment detection, and fallback.

### Error Localization

Verify `localized_message()` returns translated text for user-facing variants and falls through to `#[error]` for internal variants.

### Visual Regression

Run `just vhs` after extraction to confirm TUI renders identically with English strings. Existing `TestBackend` tests continue to work since English strings are unchanged.

### What Not to Test

- Individual lookups for all 130 keys (compile-time bake guarantees loading)
- Thread safety of `set_locale` (`rust-i18n`'s responsibility)
- Complex pluralization (only simple one/other exists)

## Contributor Documentation

Add `docs/TRANSLATING.md` covering:

- One-paragraph overview of how the system works
- How to add a new language: copy `locales/en.yml` → `locales/{code}.yml`, translate values, `cargo test`
- Key naming convention reference
- How to test: `nixdirstat --lang {code} scan /tmp`
- Where to submit: open a PR with the new `.yml` file

Translators edit YAML only — no Rust knowledge required.

## Unicode & Character Width

### What works automatically

Ratatui's `Span`, `Line`, and `Paragraph` all use `unicode-width::UnicodeWidthStr::width()` for display width measurement. CJK double-width characters, combining marks, and emoji are measured correctly. `unicode-width = "0.2"` is already a direct dependency. crossterm writes raw bytes; the terminal emulator handles Unicode rendering.

### What needs fixing

Three spots in NixDirStat's own code use byte-length or char-count where display-width is needed. Two must be fixed during i18n work; the third is cosmetic.

**1. `format!` padding in `dir_tree.rs` and `extension_legend.rs` (must fix)**

```rust
// dir_tree.rs:118 — pads by char count, not display width
format!("{name:<name_width$}")
// extension_legend.rs:80
format!("{ext_label:<ext_width$}")
```

Rust's `format!` padding counts chars, not display columns. A CJK `FileCategory` translation (e.g., `"文書"` for `"Document"`) has 2 chars but 4 columns, producing misaligned output. Add a display-width-aware pad helper:

```rust
fn pad_right(s: &str, width: usize) -> String {
    let display_width = UnicodeWidthStr::width(s);
    let padding = width.saturating_sub(display_width);
    format!("{s}{}", " ".repeat(padding))
}
```

**2. Path truncation in `progress.rs:118-128` (must fix)**

Uses `.len()` (byte length) and `.chars().count()` for display-width decisions. The translated `"Path: "` prefix width and CJK file paths would produce incorrect truncation. Replace with `UnicodeWidthStr::width()`.

**3. Info popup label alignment in `explorer.rs` (cosmetic, deferrable)**

Labels like `"  Path:      "` use hardcoded space padding. If translated to longer or CJK text, colons misalign across rows. Since each label is its own `Span`, this is cosmetic — no layout crash. Can be addressed later with a `Table` widget or width-aware padding.

## Performance

- Static string lookups (`t!("key")`) return `Cow::Borrowed(&'static str)` — zero heap allocation, suitable for every-frame rendering.
- Interpolated lookups (`t!("key", var = val)`) return `Cow::Owned(String)` — one allocation per call. Acceptable given the TUI budget (16.6ms per frame at 60fps; benchmarked at ~171ns per interpolated lookup).
- Locale is set once at startup. No per-frame locale detection or switching.
- The acceptance criterion of "no measurable render performance regression" should be verified with `cargo bench` before and after.

## Acceptance Criteria (from issue #53)

- [ ] All user-facing strings extracted into localization layer
- [ ] English string catalog covers 100% of UI text
- [ ] Locale auto-detected from environment
- [ ] `--lang` CLI flag overrides detected locale
- [ ] Missing translation falls back to English gracefully
- [ ] Documentation for contributors on adding a new language
- [ ] No measurable render performance regression
